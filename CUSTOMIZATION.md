# Customization Guide

Use this guide when adapting Helix for a real science publication.

## Site Settings

Edit [src/config/site.ts](./src/config/site.ts) first. It controls the site name, tagline, default metadata, canonical domain, contact email, social links, newsletter form settings, contact form settings, and navigation generated from categories.

Update `siteConfig.siteUrl` before building for production. Canonical URLs, social image URLs, RSS, robots, sitemap, and JSON-LD all depend on it.

Before publishing a customized copy, run `npm run release:check` and confirm the production domain, social image, contact email, demo content, image credits, and legal pages are correct for the publication.

The default newsletter and contact forms have empty actions, so they do not send reader data to an external provider. Connect them to the publication's chosen provider before launch.

## Categories

Categories live in one place: [src/config/categories.ts](./src/config/categories.ts). Add, remove, or rename categories there, then update demo posts so every `category` frontmatter value still matches the allowed list.

Header and footer navigation are generated from that same category list in [src/config/site.ts](./src/config/site.ts). You do not edit navigation labels or URLs separately unless you customize the layout components.

Category archives use Astro's static pagination in [src/pages/category/[category]/[...page].astro](./src/pages/category/[category]/[...page].astro), with four stories per page by default. The All Stories archive in [src/pages/posts/[...page].astro](./src/pages/posts/[...page].astro) uses 12 stories per page. Change the relevant `pageSize` value to adjust either archive.

Each category has an archive/about-page description in `categoryMeta`.

## Authors

Author index and profile pages are generated automatically from post bylines. The index lives at `/author/`. If a post has:

```yaml
author:
  name: "Leah Morgan"
  role: "Earth systems editor"
  bio: "Leah Morgan covers climate observations, Earth systems, and the infrastructure behind long records."
```

the theme generates a profile at `/author/leah-morgan/` and links the author name from article bylines.

There is no separate author configuration file in Helix. To change an author's name, role, or bio, update the `author` object in the relevant post frontmatter. If multiple posts use the same author name, the first available bio is used for the generated author profile.

Author URLs are generated from names with lowercase words and hyphens. For example, `Mara Chen` becomes `/author/mara-chen/`.

## Posts

Posts live in [src/content/posts](./src/content/posts). Each post should be a folder with an `index.md` file:

```txt
src/content/posts/my-story-slug/
  index.md
  story-image.jpg
```

Required frontmatter is validated in [src/content.config.ts](./src/content.config.ts). A typical post looks like:

```yaml
---
title: "A Reef's Night Chorus Offers a Faster Clue to Recovery"
description: "Hydrophones can reveal ecological activity that visual surveys miss."
category: "Life"
date: 2026-07-16
readingTime: 7
author:
  name: "Iris Novak"
  role: "Life sciences reporter"
  bio: "Iris Novak covers ecology, marine biology, and field instrumentation."
articleType: "Field Report"
researchStatus: "Field report"
audience:
  - "Ecology readers"
tags:
  - "reefs"
  - "acoustics"
image:
  src: "./story-image.jpg"
  alt: "A colorful coral reef beneath clear water"
  caption: "Reef soundscapes can change before visual surveys show obvious recovery."
  credit: "Photographer Name from Unsplash"
  creditUrl: "https://example.com/photo"
  width: 1600
  height: 1000
featuredState: "featured"
trending: true
keyFindings:
  - "Acoustic surveys can monitor reefs without constant diver presence."
methodology: "Helix summarizes established passive-acoustic monitoring methods."
sources:
  - label: "NOAA passive acoustic monitoring"
    url: "https://example.com/source"
---
```

Use `draft: true` to keep a post out of front-end lists and generated routes.

Use `featuredState: "lead"` for the dominant homepage story and `featuredState: "featured"` for secondary homepage stories. Keep only one lead story for the cleanest homepage result.

Supported `articleType` values are `Discovery`, `Explainer`, `Field Report`, `Interview`, `Analysis`, and `Visual Investigation`.

Supported `researchStatus` values are `Peer-reviewed study`, `Preprint`, `Analysis`, `Field report`, `Interview`, and `Explainer`.

Optional article fields include `updatedDate`, `doi`, `researchLink`, `corrections`, `figures`, `audience`, `tags`, `keyFindings`, `methodology`, `sources`, `trending`, and `draft`.

## Article Pages

Article pages are generated by [src/pages/post/[slug].astro](./src/pages/post/[slug].astro). They include a wide article header, visible image credit, author and date metadata, key findings, article body, source list, optional author bio, table of contents, research-status summary, DOI/research links, share links, print action, previous/next navigation, related stories, and Article JSON-LD.

Related stories are chosen by category first and then by publication date in [src/lib/posts.ts](./src/lib/posts.ts).

Markdown supports standard headings, lists, links, block quotes, images, footnotes, and code blocks.

## Homepage Sections

The homepage is assembled in [src/pages/index.astro](./src/pages/index.astro). It uses helper functions from [src/lib/posts.ts](./src/lib/posts.ts) to sort posts and pull category groups into distinct editorial layouts: a full-bleed lead story, latest briefing, editor-selected rail, category image slider, Field Notes feature, Earth and Space pairing, Life and Health pairing, newsletter band, Physics and Technology sections, and compact latest-story list.

The lead story comes from the newest visible post with `featuredState: "lead"`, falling back to the newest visible post. Secondary featured slots come from posts with `featuredState: "featured"`.

The `Worth your time` rail uses posts marked `trending: true` first and fills remaining slots with latest visible posts.

The category slider automatically creates one portrait card per entry in `src/config/categories.ts`, using the newest post image and the category's total story count. Its native horizontal rail works with touch and trackpads without JavaScript; the inline homepage script adds progress, arrow controls, and mouse dragging.

## Navigation and Search

The masthead in [src/components/SiteHeader.astro](./src/components/SiteHeader.astro) contains desktop category links, a search trigger, and a keyboard-accessible mobile navigation drawer.

Header search opens as a native `dialog`. It fetches `/search-index.json` on demand, falls back to a small inline latest-story dataset, and filters story titles, descriptions, categories, authors, and tags in the browser.

The standalone search page lives at [src/pages/search.astro](./src/pages/search.astro). It embeds the searchable dataset directly, supports the `q` query parameter, and is marked `noindex`.

The JSON endpoint lives in [src/pages/search-index.json.ts](./src/pages/search-index.json.ts). By default it exposes:

```ts
{
  title,
  description,
  href,
  category,
  author,
  authorHref,
  tags,
  status,
  date,
}
```

For small and medium publications, browser search is intentionally simple and easy to customize. Very large archives or full-body search should use a generated inverted index or a hosted search service instead.

## Newsletter

The newsletter form is intentionally provider-neutral. Configure it in `siteConfig.newsletter`:

```ts
newsletter: {
  enabled: true,
  action: "https://example.com/newsletter",
  method: "post",
  nameFieldName: "name",
  emailFieldName: "email",
  eyebrow: "The Helix Brief",
  title: "A sharper weekly signal from the research world.",
  description: "New observations, careful explainers, and field notes from the editors.",
}
```

The newsletter appears on the homepage, category archives, tag pages, author profiles, and the changelog page. Leave `action` empty while the form is only a visual starter. For production, connect it to your email provider or replace [src/components/NewsletterSignup.astro](./src/components/NewsletterSignup.astro) with provider-specific markup.

Set `newsletter.enabled` to `false` to hide every rendered instance of `NewsletterSignup`.

## Contact Forms

The contact page uses `siteConfig.contact`:

```ts
contact: {
  enabled: false,
  action: "",
  method: "post",
  office: ["Editorial desk", "Remote science newsroom"],
  responseTime: "Usually within three business days.",
}
```

When `contact.enabled` is `false` or `contact.action` is empty, the form posts to `#`. For production, connect the action to a form provider or replace [src/pages/contact.astro](./src/pages/contact.astro) with your preferred backend.

## Images

Post images should live beside each post's `index.md` file and be referenced with relative paths such as `./story-image.jpg`.

Theme-controlled post images are optimized automatically during `npm run build`. Helix renders them through [src/components/OptimizedImage.astro](./src/components/OptimizedImage.astro), which uses Astro's image pipeline to generate responsive WebP sources with JPG fallbacks, `srcset`, `sizes`, and high-priority hints for LCP images. Buyers can add a normal JPG, PNG, or WebP in a post folder; the production HTML will point visitors to generated files in `dist/_astro/`.

This optimization applies to images rendered by Helix components, such as post heroes, homepage features, archive thumbnails, category cards, and mobile-menu latest-story cards. Raw Markdown image syntax inside article bodies is not routed through `OptimizedImage.astro` by default.

Every post image needs useful alt text, a caption, credit text, dimensions, and ideally a credit URL. Astro preserves explicit dimensions to reduce layout shift. Source images should still be reasonably sized before shipping a production site.

The default social preview image is [public/og-image.png](./public/og-image.png). Replace it before launch and keep `siteConfig.socialImage` pointed at the new image.

## Icons

Social icons are hosted locally in [src/icons/bootstrap](./src/icons/bootstrap) and rendered through [src/components/LocalIcon.astro](./src/components/LocalIcon.astro). To add a new social network, add its SVG to that folder, register it in `LocalIcon.astro`, then map the label in the component that renders the link.

The bundled SVGs come from Bootstrap Icons and include their MIT license notice in the icon folder.

## Pages

Core static pages live in [src/pages](./src/pages):

- `about.astro`
- `contact.astro`
- `privacy.astro`
- `standards.astro`
- `changelog.astro`
- `search.astro`

Replace the starter copy with publication-specific masthead, editorial, corrections, privacy, and legal information.

## Production Checklist

Before deployment:

- Replace `siteConfig.siteUrl`, the example contact email, social destinations, and the default social image as needed.
- Connect or intentionally remove the newsletter and contact form actions.
- Replace demo stories, image credits, methodology notes, and legal copy with publication-specific content.
- Confirm every externally sourced image may be used under its provider's terms and retain the visible credit fields.
- Confirm article research-status labels and source lists match the visible story content.
- Run `npm run release:check`.
- Verify the generated canonical URLs, sitemap, RSS feed, robots file, and social preview on the production domain.
- Test navigation, search, pagination, forms, sharing, print styles, and the mobile drawer with a keyboard.

## Theme Tokens

Global colors, typography, borders, focus styles, and motion rules live in [src/styles/global.css](./src/styles/global.css). Prefer editing tokens near the top of that file before changing individual components.

Helix uses these core color tokens by default:

- Midnight navy `#071522`
- Scientific blue `#2864DC`
- Spectral cyan `#16B8C4`
- Signal mint `#A7F3D0`
- Ice background `#F3F7F9`
- Graphite text `#17212B`

Fonts are self-hosted in [public/fonts/helix](./public/fonts/helix):

- Geist Sans for display text
- Source Sans 3 for body text
- IBM Plex Mono for metadata and code
